# Growth strategy

Grant's growth engine is the two-sided loop between agent builders and users, primed by a wedge that requires
neither side to exist yet.

## Phase 0 · grow without a network (now)

The cold-start answer is that Grant is useful at *n = 1*: Grant's own first-party agents (SubManager, TravelBooker,
GroceryRunner) give a lone user the full hire → limits → fire experience with no marketplace liquidity required.
Every buildathon demo, video, and doc page markets the same single gesture (the permission sheet), because one
legible gesture spreads further than a feature list.

## Phase 1 · supply-side seeding (Wave 2)

Agent builders are the multiplying side: each builder who lists brings their existing users to Grant to hire them.
The listing SDK is therefore the growth product: a manifest file plus a credential check, deliberately smaller than
integrating a payments provider. The pitch to builders is conversion: "your signup dies at the
give-me-your-password step; replace it with a permission sheet." Receipts compound this: a builder's provable track
record is portable marketing they cannot get anywhere else, which makes listing sticky.

## Phase 2 · demand-side pull (Wave 3)

The verification API turns merchants into distribution: a checkout that displays "agent purchases accepted,
receipt-verified" educates every shopper about Grant at the merchant's expense. Meanwhile passkey onboarding removes
the last consumer friction (the wallet), so campaigns can target non-crypto audiences honestly.

## Channels, ranked by expected yield

1. **The Midnight ecosystem itself:** hackathon visibility, ecosystem showcases, and being *the* reference
   delegation infra other builders import (every AgentPass integration is distribution).
2. **Agent-builder communities:** where the credential pain is felt daily; developer content ("stop storing user
   passwords") outperforms consumer ads at this stage.
3. **The agentic-commerce news cycle:** AP2/ACP announcements spike exactly Grant's search terms; positioned
   commentary ("here is the private version") rides unpaid traffic.
4. **Consumer channels last**, only after passkeys: paying for consumers who then hit a wallet install would buy
   churn.

## Metrics that matter

Hires (credentials issued), receipts per credential (is delegation *used*, not merely tried), fire-rate (low is
trust working; spikes are an early-warning signal), listed agents, and verification calls. Vanity metrics explicitly
ignored here: wallet connects and page views: a connect that never hires is a UX failure, not growth.
